# Двусторонний физический тест комнаты: отставание пришедшего голоса от местного минуса

## Цель

Измерить на **конечном выходе принимающего ПК**, насколько пришедший через комнату голос
отстаёт от местного минуса, отдельно в направлениях host → laptop и laptop → host. Голос
настоящий: оригинальный вокал песни звучит из динамика передающего ПК, его слышит настоящий
микрофон, и он идёт обычным путём комнаты. Минус и оригинальный вокал в песне синхронны,
поэтому их взаимный сдвиг внутри одного выхода и есть искомая задержка.

Диагностический WAV/пилот вместо микрофона **не используется**. Его можно применять только
после теста для локализации причины.

## Конфигурация

| | ПК1 — host (основной) | ПК2 — guest (ноутбук) |
|---|---|---|
| Доступ | `D:\Git\karaoke_new_version` | `ssh pro10@192.168.0.194`, `C:\Users\pro10\Documents\karaoke_new_version` |
| Драйвер в UI | ASIO | Windows |
| Устройство | Audient USB Audio ASIO Driver (вход и выход) | системные по умолчанию |
| Частота / буфер | 48 кГц / 64 кадра | 48 кГц / период вывода 480 |
| Выход | ASIO → мониторы Audient | WASAPI Shared → динамики ноутбука |
| Вход | ASIO, микрофон Audient | «Минимальная задержка микрофона» = ON → WASAPI Exclusive |
| Exclusive-период входа | — | фактический из `RuntimeInputPeriodFrames` (ожидается 480: минимум драйвера 240 отклонён испытательным сроком как нестабильный, `LowLatencyMicrophonePeriodChoice: DEVICE_DEFAULT`) |
| Калибровка | акустическая калибровка не требуется; записать фактическое `AcousticCalibrationOrigin` | то же |
| Monitoring | OFF | OFF |

Версия кода: ветка `acoustic-optional-measure-play`, HEAD записать в REPORT.md (на обоих ПК
одинаковый).

Комната — обычная, через UI: «Онлайн-комната» → «Создать комнату» на ПК1, «Войти в комнату»
по коду на ПК2. Песня — одна, достаточно длинная (≥ 2.5 мин), есть на обоих ПК; в этом
тесте «Мне 25 — Киньте Копеечку».

## Уровни (ручки консоли караоке, обычный UI)

| Роль | Музыка | Вокал (оригинальный) | Мик | Удалённый голос | Микрофон в комнате |
|---|---|---|---|---|---|
| Передающий ПК | 0 % | 100 % (физически звучит из динамика) | 100 % | 100 % | включён |
| Принимающий ПК | 100 % | 0 % | — | 100 % | **выключен** (кнопка микрофона комнаты), чтобы на его выходе был только пришедший голос |

Громкость динамика передающего ПК подобрать так, чтобы `InputPeak` его микрофона во время
вокала был заметно выше фона (ориентир > 0.05) и без клиппинга (`InputClipping: 0`).

## Перед каждым прогоном зафиксировать (оба ПК, `AudioControl GetDiagnostics`)

`Backend`, `InputMode`, `OutputMode`, `RuntimeInputPeriodFrames`, `LowLatencyMicrophonePeriodChoice`,
`RoomPlayoutDelayFrames`, `RoomRequestedDelayFrames`, `RoomCompensationFrames`,
`RoomReturnRequirementFrames`, `RoomArrivalRequirementFrames`, `NetworkDirectPeerCount`
(1 = прямой путь, 0 = relay), `NetworkRoundTripMs`, `AcousticCalibrationOrigin`,
`AcousticCalibrationValid`, `MonitoringEnabled`, `MicrophoneEnabled`.

Endpoint AudioControl: `AD_VOICE_AUDIO_ENDPOINT=\\.\pipe\ADVoice.AudioService.Dev.v1`.

## Прогон 1: host → laptop (принимает ноутбук)

1. Комната собрана, оба окна в библиотеке.
2. На ПК1 (host) открыть песню из библиотеки — запустится общая песня в комнате.
3. Сразу выставить уровни: ПК1 — передающий, ПК2 — принимающий (таблица выше).
4. На **ПК2** записать конечный выход: обычная пользовательская запись остановить
   (`AudioControl StopRecording`), затем
   `AudioControl PrepareRecording id=dir-host-to-laptop path=<артефакты>\host-to-laptop-master.wav tap=master`
   и `AudioControl StartRecording`. Tap `master` — тот же PCM, что уходит на выход (до
   системной громкости Windows).
5. Дать песне доиграть до конца. Каждые 15 с снимать диагностику обоих ПК (counters ниже).
6. По окончании: `AudioControl StopRecording` на ПК2, вернуться в библиотеку.

## Прогон 2: laptop → host (принимает основной ПК)

Зеркально: ПК2 — передающий (Музыка 0, Вокал 100 % из динамиков ноутбука, «Минимальная
задержка микрофона» ON), ПК1 — принимающий (Музыка 100, Вокал 0, микрофон комнаты выключен).
Песня та же, снова запускает host. Запись конечного выхода — на **ПК1**:
`path=<артефакты>\laptop-to-host-master.wav tap=master`.

## Что нельзя менять между направлениями

Комнату (дедлайн, политику, route), буферы, периоды, устройства, драйверы, галочку
low-latency mic, режим мониторинга. Меняются только уровни и mute микрофона комнаты.

## Как измерять отставание голоса от минуса

Входы: `*-master.wav` принимающего ПК, стемы песни (минус `instrumental` и оригинальный
вокал `vocals` — пути, которые AudioService загрузил командой `LoadSong`; взять с
принимающего ПК).

1. Окна по 20 с: **начало** — 20–40 с позиции песни, **середина** — центр песни ±10 с,
   **конец** — последние 40–20 с до конца. Позицию песни в файле получить из шага 2.
2. Минус: кросс-корреляция окна master с минусом (4 кГц, огибающая не используется) →
   смещение минуса в файле `b`.
3. Голос: из окна вычесть минус, выровненный по `b` и подобранный по амплитуде (МНК); остаток
   полосой 300–3400 Гц коррелировать с оригинальным вокалом → смещение голоса `v`.
4. Отставание = `v − b` в мс. Нет пика корреляции (нормированный максимум < 0.2) — окно
   «голос не найден», **не ноль**.

## Drift

Drift есть, если отставание в конце отличается от начала больше чем на 5 мс, либо отставания
трёх окон монотонно растут/падают с суммарным изменением > 5 мс.

## Реальные пропадания

По всему файлу после выравнивания: огибающая 20 мс у пришедшего голоса (остаток после вычитания
минуса, 300–3400 Гц) и у оригинального вокала, сдвинутого на найденное отставание. Пропадание —
участок ≥ 60 мс, где оригинальный вокал активен (выше −35 dB от своего медианного уровня
пения), а пришедший голос ниже −30 dB от своего медианного уровня пения. Каждый участок
указать с позицией и длительностью; отдельно сопоставить с сетевыми counters. Счётчики сами
по себе пропаданием не считаются.

## Counters для сохранения (каждые 15 с, оба ПК)

`NetworkPacketsSent/Received`, `NetworkStaleBlocks`, `NetworkReceiveQueueOverruns`,
`NetworkDroppedSendBlocks`, `NetworkSendGapMaximumMs`, `NetworkRoundTripMs`,
`NetworkDirectPeerCount`, `RemoteMixNonzeroBlocks`, `RemoteMixPeak`,
`RoomVoiceUpstreamNonzeroBlocks`, `RoomPlayoutDelayFrames`, `RoomCompensationFrames`,
`ClockBridgeUnderruns/Overruns`, `MicCaptureSkippedFrames/RepeatedFrames`,
`CaptureDiscontinuities`, `XRuns`, `MusicUnderruns`, `InputPeak`, `InputClipping`,
`InputMode`, `OutputMode`, `RuntimeInputPeriodFrames`.

## После теста вернуть

Уровни: Музыка 100 %, Вокал по умолчанию, Мик 100 %, микрофоны комнаты включены, Monitoring OFF;
выйти из комнаты. Драйверы и галочку не трогать (ПК1 — ASIO, ПК2 — Windows + ON).

Результаты — в `REPORT.md` рядом; этот план после теста не правится.
