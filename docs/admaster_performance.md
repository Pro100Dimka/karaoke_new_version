# AD Master: ускорение с сохранением результата

Изменения следуют после исправлений качества в `fad1e541f71326821553a3380530c76cf3c11d94`.
Все измерения ниже относятся к трём зафиксированным native-записям и одному CPU-окружению.

## Что ускорено

1. В пределах одного `MasterRender` признаки неизменённого вокала и референса используются повторно. Размер, device, inode, `mtime_ns` и `ctime_ns` проверяются перед повторным использованием; изменение файла во время анализа вызывает ошибку. Массивы доступны только для чтения, отмена проверяется и при попадании в кэш. Принятая коррекция нот и изменённые выходы вставок измеряются отдельно. На воспроизведённом пути число полных анализов снизилось с 11 до 9.
2. pYIN рассчитывает таблицу тех же распределений Больцмана один раз на вызов pYIN и находит локальные минимумы пакетно. Последующие вероятности, интерполяция, Viterbi, сетка нот, размеры окон и пороги уверенности сохранены. Адаптер использует отдельный словарь globals, не меняя Librosa. Он включается только для проверенной версии 1.0.0 и ожидаемого интерфейса; другой интерфейс или диапазон свыше 512 периодов использует исходный расчёт. Кэш адаптера учитывает обе функции, включая private helper. В контрольном примере 201 повторный вызов PMF заменён одним.
3. Региональный ревербератор пропускает FFT только при точно нулевом возбуждении. Остаток предыдущего импульса продолжает выводиться на каждом блоке; слабые ненулевые звуки не отсекаются. В профилированной записи 10 временные границы ограничивают число пар FFT величиной 205 вместо 1552.
4. При калибровке конкретного регионального посыла измеряется только используемая частотная полоса. Остальные вызовы продолжают получать обе полосы. Состояние выбранного фильтра и порядок расчёта энергии сохранены; для записи 10 число фильтраций калибровки снизилось с 768 до 384.

## Измерение полного рендера

Базовая и изменённая реализации запускались по три раза для каждой записи, всего 18 рендеров. Порядок состояний чередовался, все задания выполнялись последовательно. OMP, OpenBLAS, MKL и Numba использовали одинаковое ограничение в два потока. GPU не использовался.

- Решения timeline, arrangement, pitch, EQ, компрессии, баланса, ducking, посылов, мастеринга и контроля качества совпали точно. Из сравнения исключены только три поля времени выполнения: `processing.stageSeconds`, `processing.elapsedSeconds`, `processing.mix.timingsSeconds`. Музыкальные временные метки сохранены.

- Полный backend gate после последних изменений: **2458 passed, 10 skipped, exit 0**, включая архитектуру, форматирование, lint и типы. Ни один прежний тест или порог не ослаблен.
