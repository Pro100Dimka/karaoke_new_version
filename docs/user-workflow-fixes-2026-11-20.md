## Исправленные пути

| Сценарий | Причина и изменение |
| --- | --- |
| Пользователь подключает микрофон в открытой песне | Доступность входа больше не остаётся результатом первой загрузки. Она обновляется при восстановлении аудио/смене настроек и перед началом дубля. Запоздалый ответ старого запроса игнорируется. |
| Меняется буфер или частота при выбранном System Default | Новая настройка строится из сохранённого выбора пользователя; фактические runtime ID больше не подменяют выбор по умолчанию. |
| Вход занят другой программой | Явный native `DEVICE_IN_USE` в открытой сессии отображается как занятый вход, а не готовый микрофон. |
| Сохранение изменённых нот | Пересоздаётся соответствующий melody guide, его checksum публикуется вместе с новой ревизией. Старые ревизии и общие аудиофайлы не изменяются. Сохранение только текста не вызывает рендер аудио. |
| Прослушивание после Save | Редактор подхватывает новую мелодию и сохраняет позицию, скорость, тональность и состояние паузы/воспроизведения. Следующий Save восстанавливает preview после временной ошибки аудио; поздний ответ после перехода к другой песне не запускает старую. |
| Повторный анализ после редактирования песни | Результат сверяется с неизменяемой версией песни, под которую сделан дубль. Новая активная редакция больше не делает успешный анализ старой записи недоступным. Проверки другой песни/ревизии и старого алгоритма сохранены. |
| AD Master для старой записи после WAV → FLAC | Восстановление голоса находит прежний backing companion независимо от нового расширения основного файла. Приоритет сохранённого lossless original сохранён. Вычитание из MP3 запрещено; ненужная AI Separation для lossless legacy-layout не запускается. |
| Ошибка AD Master или импорта | Асинхронный job сохраняет код, сообщение и детали причины. Известные причины локализованы; неизвестная причина backend не заменяется одним общим «не удалось». |
| Удаление записи из окна анализа | Удалённый дубль не подменяется выдуманным DTO с пустым путём. Его анализ закрывается и поздний ответ не открывает его вновь. Сохранённый Master без исходного дубля остаётся доступен, без плеера несуществующего оригинала. |
| Импорт и отмена в очереди | Placeholder и реальный job объединены; после импорта карточка передаётся обработке. Можно отменить как выполняющийся job, так и ожидающий в очереди; локальная карточка без backend job ещё не предлагает отмену. Импорт отменяется общим API, SongProcessing — специализированным API со сменой статуса песни. Кнопка воспроизведения доступна только готовой песне. Посторонние model/recording jobs не показываются в очереди песен. |
| Уточнение слов и повторная попытка | Возвращён доступный из настроек сценарий уточнения. Retry сохраняет режим lyrics, включая прямую кнопку карточки. ManualLyricsConflict предлагает отдельное подтверждение возврата к AI, привязанное к точной ревизии. Cancel/RevisionConflict не запускают обработку. |
| Импорт известной старой ревизии | SafeOnly больше не скрывает более новые отличающиеся ручные правки. Для такого отката нужен AcceptOlder; обе ревизии сохраняются. Эквивалентная повторная активация остаётся идемпотентной. |
| Перенос пользовательской обложки | Пакет включает выбранную Custom-обложку отдельным проверяемым артефактом. Импорт сохраняет существующую Custom/override; копирование и изменение метаданных связаны общей транзакцией media update. Старые пакеты продолжают читаться. |
| Повторный импорт архива библиотеки | Для существующей песни добавляются отсутствующие записи, включая удалённые дубли с сохранённой историей и Master без удалённого original. Повторы не создают копий. Проверяются собственные сохранённые версии песни у дублей и анализов; несовместимые ссылки отклоняются до публикации. Существующие песни и ревизии не объединяются и не перезаписываются. Отчёт показывает добавленные/пропущенные песни и записи, открытый список записей обновляется сразу. Старые отчёты без счётчиков записей поддерживаются. |

## Проверка

Каждый подтверждённый дефект сначала воспроизведён отдельной регрессией. После правок запускались только затронутые сценарии и их непосредственные потребители.

- Backend: 19 проверок анализа/старых записей, 15 проверок редактора, 9 проверок импорта/отката проектов прошли.
- После добавления обложек: 37 проверок пакетов, включая сохранность локальной обложки, старые пакеты, отмену, ошибку БД и потребителей отката/идемпотентного импорта, прошли.
- Дополнение архива библиотеки: 15 backend-проверок прошли — 12 новых регрессий и 3 непосредственно затронутых потребителя импорта. Проверены новые и удалённые дубли, повторный импорт, исторические анализы, конфликты ссылок, retained Master и кеширование проверки одной ревизии. Независимое чтение готового diff не выявило блокирующих проблем с сохранностью существующих данных и откатом.
- Настоящий FFmpeg восстановил голос из lossless legacy-исходников; короткий AD Master API завершился Succeeded без Separation-провайдера. Исходные файлы сохранили свои байты.
- Реальное сохранение MIDI 69 → 81 изменило guide с примерно 440 на 880 Гц. Настоящий Electron resolver передал в LoadSong именно FLAC сохранённой ревизии; измеренная частота — 880.039911 Гц.

Здесь использованы Linux, существующий Python venv и доступные frontend-зависимости. Их версии могут отличаться от lockfile поставляемой сборки. Это проверка изменений, а не сборка релиза.

Полные suites, Windows CI, тяжёлая нейросетевая обработка и сторонние benchmarks не запускались. Работающий сервер и реальные пользовательские песни/записи не изменялись.
