## Что исправлено

### 1. Ctrl+S создавал ревизию даже без правок

Кнопка сохранения в редакторе была отключена для неизменённого документа, но горячая клавиша всё равно отправляла запрос сохранения. Backend на каждый такой запрос публикует новую ревизию проекта. Это происходило сразу после открытия редактора, после Undo к сохранённому содержимому и при повторном Ctrl+S после успешного сохранения.

`useEditorSession.persist` теперь использует существующее сравнение содержимого `isEditorDirty` до обращения к backend. Если изменений нет, новая ревизия не создаётся. При этом повтор после сбоя аудиопредпрослушивания по-прежнему подготавливает уже сохранённую ревизию. Проверка поколения сессии и актуальных правок после ожидания сохраняет защиту от перехода к другой песне или новых изменений во время подготовки.

Это убирает лишние ревизии и работу по их публикации. Утверждения, что раньше каждая такая ревизия физически дублировала всё аудио, нет: backend может использовать hard links. Уже существующие ревизии не удаляются.

Production-файл: `frontend/src/pages/editor/useEditorSession.ts`.

### 2. При первой обработке не загружалась звуковая волна песни

Карточка обрабатываемой песни передаёт её настоящий `activeRevision`, который до первого опубликованного проекта равен `0`. В Electron обработчик `waveformPeaks` вызывал строгую проверку положительной ревизии до блока перехода к исходному аудио. Поэтому запрос завершался `Invalid project identity`, хотя backend уже умел строить волну исходной импортированной песни. Карточка оставалась без волны, а ошибка попадала в механизм ошибок waveform.

Для запроса волны теперь допустима нулевая ревизия: она сразу читает управляемый исходник через существующий backend endpoint. Положительные ревизии сначала используют опубликованную инструментальную дорожку, а при недоступности её волны сохраняют прежний переход к исходнику. Проверки идентификатора и отрицательных, дробных или небезопасных числовых ревизий остаются до чтения. Общие правила разрешения проигрываемых артефактов не ослаблены: им по-прежнему нужна положительная ревизия.

Production-файл: `frontend/electron/ProjectFiles.ts`. Backend и построение звуковой волны не менялись.

### 3. Массовое удаление показывало `[object Object]`

При отказе удаления backend возвращает структурированный `AppError`. Например, `DeleteSong` отвечает `LibraryInUse`, когда фоновые задачи ещё используют библиотеку. Массовое удаление преобразовывало такой объект через `String(error)`, и пользователь видел название песни с `[object Object]` вместо объяснения.

Обработчик теперь применяет общие `toAppError` и `errorstring`: известные причины показываются локализованным сообщением, неизвестный код сохраняет текст backend. Название проблемной песни остаётся в уведомлении. Сохранено частичное выполнение: успешно удалённая песня исчезает, неудачная остаётся выделенной для повторной попытки.

Production-файл: `frontend/src/pages/library/songs/index.tsx`. Порядок удаления и его backend-ограничения не менялись.
