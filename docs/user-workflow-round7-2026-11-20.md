# Исправления импорта, настроек песни и менеджера моделей — 20 ноября 2026

Исходная ревизия: `5a015a7ae8fc0516a448638beeeae7605e57b2ce`, ветка `main`.

В этом проходе подтверждены и исправлены пять проблем обычных пользовательских сценариев. Изменения охватывают форму настроек песни, управление моделями и чтение метаданных/текста при импорте. Для дефектов сначала получены воспроизведения до production-правок.

## Исправления

### 1. Сохранение настроек откатывало новые данные песни

Пока окно настроек оставалось открытым, библиотека могла получить обновлённые название, исполнителя и язык. Форма намеренно сохраняла свой черновик, но при Save отправляла все первоначальные поля. Поэтому изменение только темпа откатывало распознанные метаданные, а изменение только исполнителя откатывало название и язык. Отправленные нетронутые поля также помечались backend как ручные переопределения.

Теперь название, исполнитель и язык сравниваются со значениями при открытии окна. В PATCH отправляются только поля, которые пользователь действительно изменил. Сравнение с исходными значениями формы позволяет отличить его правку от обновления props. Явная очистка исполнителя по-прежнему отправляет пустую строку. Сохранение медиапутей, локальных настроек и черновика после ошибки осталось прежним.

Проверен настоящий путь `libraryChanged` → обновление запроса той же песни → новые props без перемонтирования формы. Production-правка ограничена `frontend/src/pages/library/modals/song-settings/index.tsx`; контракт backend не менялся.

### 2. У загрузки модели в очереди отсутствовала отмена

Backend создаёт задачу загрузки раньше, чем worker начинает работу и меняет строку модели с `Missing`/`Failed` на `Downloading`. Интерфейс запрашивал задачу только для уже загружающейся или проверяемой модели. В обычном ожидании свободного worker он снова предлагал «Скачать» и не показывал «Отменить».

Менеджер теперь учитывает состояние задачи независимо от строки модели. Ожидающую загрузку можно отменить и затем повторить. Пока начальное состояние задачи неизвестно или его запрос завершился ошибкой, повторная загрузка заблокирована; при ошибке доступен повтор запроса. Для простаивающих моделей не добавлен опрос каждую секунду: периодический опрос используется только при активной задаче/работе модели, остальные обновления приходят через существующий механизм событий и обновления запросов.

При просмотре изменения отдельно найден и устранён переходный дефект: устаревшая кнопка повтора запроса могла оставаться после успешной установки модели. Новый сценарий сначала воспроизвёл его; финальная версия скрывает эту кнопку для `Ready`.

### 3. Ошибка удаления модели скрывала настоящую причину

Удаление установленной модели во время фоновой работы может получить `ModelsInUse`. Структурированный `AppError` преобразовывался через `String()`, и пользователь видел `[object Object]`. Теперь известные коды получают локализованное объяснение, а неизвестные сохраняют сообщение backend. После отказа модель остаётся в списке, повторная попытка доступна.

Две правки менеджера моделей находятся в `frontend/src/pages/library/modals/settings/ai/models.tsx` и `model-download.tsx`. Код загрузчика backend не менялся.

### 4. Импорт OGG/Opus терял название, исполнителя, альбом и текст

На настоящих коротких OGG/Opus-файлах ffprobe возвращает эти теги в аудиопотоке, а инспектор читал только теги контейнера. В результате файлы с заполненными метаданными импортировались с именем файла и `Unknown Artist`; встроенный текст также терялся.

Теперь инспектор сначала использует метаданные контейнера, затем заполняет недостающие значения тегами первого аудиопотока. Теги видео/обложки и последующих аудиопотоков не смешиваются с данными песни. Сохранён приоритет контейнерного `unsyncedlyrics` перед текстом аудиопотока.

Дополнительное воспроизведение показало ту же потерю для `Title`, `Artist`, `Album`, `Lyrics`: ffprobe сохранял смешанный регистр ключей. Добавлен регистронезависимый поиск после прежних приоритетных вариантов нижнего/верхнего регистра; пустые и нестроковые значения пропускаются. Название по имени файла и прежний fallback исполнителя сохраняются при отсутствии подходящих тегов.

Production-файл: `python/backend/infrastructure/ffmpeg_media.py`. Исходное аудио не переписывается. Исправление действует при последующих импортах; уже импортированные песни автоматически не мигрируются.

### 5. Текст UTF-16 рядом с песней ломал импорт аудио

Соседний `.txt` или `.lrc` в UTF-16 LE/BE с BOM приводил к `UnicodeDecodeError`, и вся задача импорта аудио завершалась ошибкой. UTF-8 с BOM импортировался, но маркер кодировки оставался перед первым словом.

Чтение теперь поддерживает UTF-8 с BOM/без него и UTF-16 LE/BE с явным BOM. Маркер не попадает в текст песни; нормализация Windows CRLF и одиночных CR сохраняет прежнее поведение `read_text`. Кодировка не угадывается для произвольных байтов. Общий префикс UTF-32 LE специально не принимается за UTF-16; неподдерживаемый или повреждённый текст по-прежнему вызывает ошибку вместо молчаливого искажения.

Production-файл: `python/backend/infrastructure/sidecar_lyrics.py`. Исходные аудио- и текстовые файлы не изменяются.
