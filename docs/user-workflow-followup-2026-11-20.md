# Дополнительные исправления пользовательских сценариев — 20 ноября 2026

Исходная ревизия: `a5eaf3f308c1072670a92a371b781479433733f6`.

Это отдельный проход после предыдущих исправлений. В работу включены подтверждённые сбои с конкретным действием пользователя и воспроизведением до изменения production-кода.

## Исправления

| Действие пользователя | Причина сбоя | Результат исправления |
| --- | --- | --- |
| Ещё раз запустить AD Master, пока предыдущий запрос обрабатывается | Каждый запрос создавал новый job для одного original | Повтор возвращает существующий Queued/Running/Cancelling job. После завершения, ошибки или отмены новый запуск разрешён. Обращение через уже сохранённый Master тоже разрешается к настоящему original. |
| Удалить дубль одновременно с запуском AD Master | Между чтением original и регистрацией job отсутствовала защита входного файла | Существующий механизм подготовки job удерживает входные данные до регистрации. Удаление получает LibraryInUse, исходник остаётся целым. |
| Получить готовый Master при ошибке фонового архивирования | Callback после публикации файлов и commit БД пробрасывал ошибку, превращая уже сохранённый результат в Failed | Сохранённый Master возвращается как успешный. Ошибка постановки на архивирование записывается в журнал; оригинал и результат сохраняются. |
| Нажать Play и сразу удалить ещё загружаемый дубль | Остановка по recordingId сопоставляла только уже загруженный файл | Отменяется и запрос пути, и начавшаяся native-загрузка нужного дубля. После удаления отложенный Play не выполняется. Другой активный preview сохраняется, если новая загрузка ещё не заняла его место. |
| Переключить запись, пока ответ на предыдущий Stop ещё не пришёл | Поздний Stop безусловно обнулял идентификатор уже нового preview | Состояние старого preview очищается до ожидания ответа; новый сохраняет владельца и идентификатор. |
| Удалить старый дубль, пока следующий загружается | Остановка старого увеличивала общую generation и отменяла загрузку следующего | Отмена сопоставляет владельца и целевую запись. Загрузка другого дубля продолжает работу. |
| Выйти из редактора во время уже начатого сохранения | Повторный Save сразу возвращал false, отменяя выход | Выход дожидается результата текущего сохранения; второй запрос записи не создаётся. |
| Отказаться от изменений, когда закрытие задержано другим подтверждением | Discard очищал хранилище, но оставлял грязный документ и таймер автосохранения | История возвращается к последней сохранённой версии, таймер отменяется, отвергнутый черновик не появляется снова. Если Save уже отправлен, сначала учитывается его результат, затем отбрасываются только оставшиеся изменения. |
| Держать настройки песни открытыми во время обработки | Окно хранило старый объект песни | Статус, версия проекта и BPM обновляются, введённые название и исполнитель сохраняются. Отдельный запрос открытой песни не зависит от её попадания в текущий фильтр библиотеки. Доступность редактирования также учитывает активную задачу уточнения, пока сохранённая песня остаётся Ready. |

## Подтверждение

- AD Master: исходный запуск новых регрессий — 4 failures и 3 проходящих сценария; после исправления — 7 passed. Использованы настоящие HTTP/API, executor, SQLite и публикация файлов. Для проверки управления задачами renderer заменён копированием короткого синтетического WAV; качество DSP этим запуском не оценивалось.
- Preview записей: 4 новых сценария воспроизвели сбои. После исправления прошли 30 тестов из трёх затронутых файлов, включая существующих потребителей отмены, переключения владельцев, радио и удаления.
- Редактор: воспроизведены оба исходных сбоя и пересечение Save с последующим Discard. После правки прошли 22 теста сессии редактора.
- Настройки песни: прошли 17 тестов в трёх непосредственно затронутых файлах. Отдельно воспроизведены устаревшее окно, исчезновение песни из фильтра после обработки и активное уточнение при сохранённом Ready. Проверены обновление версии/BPM, сохранение текстовых черновиков и существующий выбор песен. Полный каталог для обновления окна не читается.
- Семантическая и синтаксическая проверка 7 изменённых TypeScript-файлов прошла; архитектурные и стилевые правила применены к снимку этих файлов. Импортированные зависимости не проверялись отдельно. Python: Ruff для двух затронутых файлов, mypy с штатной целевой платформой win32 и архитектурная AST-проверка production-файла прошли. Whitespace-проверка итогового diff прошла.

Основные регрессии: `python/tests/test_studio_master_lifecycle.py`, `frontend/src/services/audioPlayers.test.ts`, `frontend/src/pages/editor/useEditorSession.test.tsx`, `frontend/src/pages/library/songs/LibrarySongs.settings.test.tsx`.

## Границы проверки

Проверки выполнялись в Linux на доступных зависимостях, только для изменённых сценариев и непосредственных потребителей. Полные suites, сборки, CI, нейросетевые модели и длительные benchmarks не запускались.

Автотесты редактора и библиотеки используют реальные React-компоненты/состояния с подменой сервисных границ. Проверки preview подтверждают команды и владение загрузкой; реальное звучание Windows AudioService этим запуском не подтверждается. Фактический Windows/Electron запуск через `start.bat` здесь недоступен. Комнатные сценарии, перенос проектов и смена аудиоустройств в этом проходе не менялись.
