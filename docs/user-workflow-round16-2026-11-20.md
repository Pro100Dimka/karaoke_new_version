База: `main`, `f53546436c835e1c29ca9959050e678ec1ee1bd8`.

В этом проходе исправлены четыре группы подтверждённых дефектов: меню эффектов в отделённой консоли караоке, принадлежность архива записей после возврата из караоке, ошибка создания каталога при импорте и потеря существующих побуквенных отметок в редакторе для отдельных Unicode-символов. ## Караоке: меню эффектов и возврат отделённой консоли

Установленный Popover подписывается на основной document, хотя меню отделённой консоли находится в другом документе. Поэтому Escape из этого окна доходил до команды выхода из караоке, а нажатие вне меню не закрывало его. Общая пересылка клавиш также не учитывала `defaultPrevented`.

В `EffectPresets.tsx` добавлены обработчики Escape и нажатия вне меню в документе фактического владельца. Escape закрывает меню и возвращает фокус кнопке. Нажатие вне меню закрывает его, сохраняя фокус выбранного контрола. `useDetachedPanel.ts` больше не пересылает уже обработанную клавишу. Следующий Escape с закрытым меню проходит в обычную команду выхода. Основное окно сохраняет поведение установленного UI kit.

Независимый просмотр выявил ещё один связанный путь: вернуть консоль с открытым меню перетаскиванием либо закрыть её отдельное окно. `DetachedPanel keepMounted` переносит тот же DOM без перемонтирования; старое меню и подписки могли остаться связаны с прежним документом. Этот дефект отдельно воспроизведён до дополнительной правки. Теперь меню закрывается по `pagehide` захваченного окна-владельца. Старые подписки снимаются, а повторное открытие использует актуальный документ.

Четыре дополнительные проверки покрывают оба способа возврата и последующее закрытие меню через Escape либо нажатие вне него. Проверяются идентичность DOM кнопки и поля, сохранение введённого текста, снятие документных подписок и отсутствие случайного выхода из караоке. Исходное предположение о таком же обычном жесте из основного окна в отдельное отвергнуто после чтения кода: обработка начального pointerdown там отличается. Оно не используется как доказательство.

## Записи: архив другой песни после возврата из караоке

Достижимая последовательность: в основном окне открыт архив песни B, на ТВ заканчивается песня A, приложение возвращает её запись для просмотра анализа. `RecordingsModal` остаётся смонтированным при замене того же маршрута библиотеки. Общий список уже становился списком A, но состояние открытого архива и цель обновления сохраняли B. Пользователь мог увидеть записи A под заголовком B, старую загрузку или ошибку; обновление списка также обращалось к B.

`openAnalysis` теперь закрывает прежний архив и сбрасывает его список, загрузку и ошибку, если вернулась другая песня. Анализ и последующее обновление используют вернувшуюся песню. Уже существующие поколения запросов блокируют поздний успех и отказ старой загрузки. Если вернулась та же песня, открытый архив сохраняется.

Проверены загруженный, ошибочный и ожидающий архивы, оба исхода позднего ответа, обновление списка вернувшейся песни и подключение появившегося мастера к её waveform. Проверяются выбранная запись, действие открытия её файла и отсутствие лишнего запуска анализа. Тесты используют реальные компоненты, hook, playback store и событие обновления; backend, desktop и audio границы заменены fixture. Источник события от ТВ прослежен по коду, живой ТВ-сеанс здесь не запускался.

## Импорт: недоступный каталог назначения

Создание `songs/<id>/source` находилось вне существующего `try` в `LocalSongStorage.copy_source`. При отказе `mkdir` синхронный API возвращал `InternalError/500`, очередь — `InternalJobError`, а в журнале восстановления оставалась незавершённая запись.

`mkdir` перенесён внутрь существующей обработки ошибок хранения. Теперь этот отказ получает код `StorageUnavailable`, доходит до штатного отката импорта и завершения записи журнала. После устранения причины можно повторить запрос с тем же `Idempotency-Key`; импорт создаёт ровно одну песню.

Обе API-ветви проверены на реальных приложении, очереди, SQLite, журнале, файловой копии и media inspector. Внедряется только отказ создания нужного каталога. Исходный WAV длительностью 0,125 с остаётся неизменным; после неудачи нет опубликованной песни и файлов проекта, после повтора копия совпадает с исходником. Внешнее распознавание заменено обычной fixture. Реальные Windows ACL, отключение диска и одновременный вторичный отказ очистки этими тестами не проверены.

## Редактор: существующие побуквенные отметки

Frontend сравнивал длину массива отметок с длиной UTF-16 строки; backend сохраняет отметки по Unicode code points. Например, у валидного слова `la😊` три отметки, а `text.length` в JavaScript равен четырём. При загрузке они отбрасывались, и обычное изменение высоты ноты с сохранением могло удалить прежнюю разметку, хотя текст не менялся.

Одно сравнение в `editorApi.ts` приведено к существующему backend-контракту через `[...word.text].length`. Нормализация текста, grapheme clusters и алгоритм временных преобразований не менялись. Проверен настоящий путь load mapping → `moveNotes` → save mapping с полным ожидаемым PUT payload. Контроли покрывают кириллицу, combining accent, нулевую и отрицательную длительность, повторный припев и округление конечной отметки. Это редкий, но конкретный случай потери данных; распространённость такого ввода не утверждается.
