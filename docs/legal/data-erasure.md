# Удаление данных и границы операции

Порядок для текущей инфраструктуры, проверка конфигурации 26 ноября 2026 года. Он описывает техническую операцию и не заменяет заполнение остальных реквизитов политики конфиденциальности.

## Управляемые данные

Кнопка удаления в приложении проверяет удостоверение владельца, останавливает передачу диагностики и отключает активность Discord. Сервер удаляет профиль, социальные связи, приглашения, историю комнат, загруженные проекты, отдельные дорожки и связанные диагностические журналы.

Задания удалённой обработки привязаны к удостоверению владельца. При удалении аккаунта очередь запрещает новые задания этого владельца и отменяет текущие. Компьютер обработчика удаляет принадлежащие владельцу сеансы, временные исходные данные и подробные журналы, затем подтверждает очистку. После этого очередь удаляет входные файлы, результаты, прогресс и строки заданий. Локальные оригиналы библиотеки не затрагиваются.

При недоступном обработчике сервер возвращает `ProcessingErasurePending`; приложение ожидает подтверждения до двух минут. Без подтверждения успешное удаление не показывается. Следует включить тот же компьютер обработчика и повторить операцию. Нельзя вручную подменять подтверждение очистки записью в базе или подтверждать её с другого компьютера, где исходные сеансы не удалялись. Текущая конфигурация рассчитана на один постоянный компьютер обработчика.

Новые версии обработчика разделяют сеансы и подробные журналы по владельцам. Старые журналы без такого разделения очищаются при первом запуске новой версии. Старые временные сеансы без владельца очищаются до приёма следующего задания. Обновление очереди с неатрибутированными старыми заданиями блокируется: они должны быть завершены и очищены до обновления. Развёртывание также блокируется при активных заданиях.

Небольшие отметки отзыва удостоверений остаются без профиля, аудио и файлов, чтобы старый клиент не создал данные заново. Их нельзя заменять полноценной историей удалённых пользователей.

## Резервные копии

В текущей конфигурации пользовательские базы, файлы и журналы не копируются в резервные архивы. Проверка Oracle API в единственном подключённом регионе `eu-frankfurt-1` показала ноль снимков загрузочного диска, обычных дисков и групп томов, ноль назначенных политик резервного копирования и ноль контейнеров Object Storage. Сервер размещён во Франкфурте, Германия.

Резервные версии развёртывания содержат код, зависимости и служебную конфигурацию. Папки `data`, пользовательские базы и журналы в пакеты развёртывания не входят. Эти версии не являются резервными копиями аккаунтов. При откате необходимо сохранить действующие пользовательские базы с отметками отзыва и использовать версию, поддерживающую удаление и очистку обработчика.

Перед включением резервного копирования пользовательских данных требуется реализовать сроки хранения, удаление либо исключение удалённых данных из восстановления и проверить, что восстановленный сервер не возвращает удалённый аккаунт. До такой проверки копирование `data`, создание образов с пользовательскими данными и назначение политик снимков не входят в поддерживаемую конфигурацию. Oracle отдельно управляет резервными копиями томов; удаление файлов внутри работающей виртуальной машины не удаляет существующий снимок.

Документация Oracle: [копии томов](https://docs.oracle.com/en-us/iaas/Content/Block/Concepts/blockvolumebackups.htm), [удаление копии](https://docs.oracle.com/en-us/iaas/Content/Block/Tasks/delete-bv-backup-volume.htm), [политики хранения](https://docs.oracle.com/en-us/iaas/Content/Block/Tasks/schedulingvolumebackups.htm).

## Независимые получатели

Функции распознавания, поиска, загрузки и Discord сохраняются. До удаления приложение прямо показывает, что его кнопка не удаляет независимые аккаунты, историю внешних сервисов и уже скачанные другими участниками копии.

| Получатель | Передаваемые данные и действие при удалении |
| --- | --- |
| Компьютер удалённого обработчика | Управляемая очистка с обязательным подтверждением, описанная выше |
| Другие участники | Сервер прекращает доступ к удалённым данным. Уже сохранённые на чужом устройстве проекты и записи не помечаются как удалённые нашей кнопкой |
| Shazam/Apple, AudD | Акустические признаки либо выбранный аудиофайл для распознавания. Независимая история и данные сервиса не удаляются нашим удостоверением аккаунта |
| LRCLIB, Pisni.ua, tekst-pesenok.online, Apple, Deezer и серверы изображений | Поисковые параметры, сведения о музыке и технические параметры прямого соединения. Удаление аккаунта приложения не является удалением этих данных у поставщика |
| Google/YouTube, GitHub, поставщики моделей и зависимостей | Запросы контента, обновлений и необходимых файлов, технические параметры прямого соединения. Приложение не получает административный доступ к истории этих сервисов |
| Discord | Текущая передача активности отключается. История Discord и его собственный аккаунт остаются под управлением Discord и пользователя |

Для независимых сервисов используются их собственные средства конфиденциальности. Не заявлять об успешном удалении их копий без подтверждения самого сервиса. Например, [политика AudD](https://audd.io/privacy/index.php) допускает сохранение сведений о распознавании, а [инструкция Discord](https://support.discord.com/hc/en-us/articles/7931156448919-Activity-Sharing-on-Discord-FAQ) отдельно описывает очистку истории активности пользователем.

## Проверка после изменения инфраструктуры

Проверить очередь и компьютер обработчика на одноразовом аккаунте: создать временное задание, дождаться наличия его файлов, удалить аккаунт через приложение, получить подтверждение обработчика, убедиться в отсутствии файлов и строк задания, затем перезапустить приложение и проверить отключённое состояние аккаунта. При выключенном обработчике успешное удаление недопустимо.

Повторить инвентаризацию всех подключённых регионов, снимков, политик, хранилищ, планировщиков и архивов после добавления поставщика или изменения развёртывания. Проверьте, что Nginx не сохраняет запросы приложения и подробные ошибки с его маршрутами. Служебные журналы обработчика должны содержать только общие сведения; подробности задания должны находиться в удаляемой папке его владельца.
