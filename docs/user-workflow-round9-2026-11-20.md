# Исправления повторного текста LRC, перетаскивания файлов и счётчика очереди — 20 ноября 2026

Исходная ревизия: `508844206fe596b4028421726f190774c861e4ed`, ветка `main`.

В этом проходе подтверждены и исправлены три пользовательские проблемы. Для каждой получен падающий тест до изменения production-кода. Изменены три production-файла и три файла тестов.

## 1. Повторный припев терялся при чтении LRC

Строка `[00:10][00:30]Припев` задаёт повтор одного текста в двух местах песни. Такой компактный формат действительно создают программы работы с LRC: например, он описан в [документации генератора ass-to-lrc](https://github.com/nattadasu/ass-to-lrc#compact-format). Это подтверждение существующего входного формата; единой универсальной спецификацией LRC данный источник не объявляется.

Прежний `decode_lrc` извлекал только первую временную метку. Вторая попадала в слова, а повторное исполнение исчезало. В настоящем queued-импорте аудио с соседним LRC и последующем `LyricsDiscovery.lookup` воспроизведены лишние числа в тексте и отсутствие повторного припева.

Парсер теперь считывает все ведущие временные метки и создаёт отдельное вхождение очищенного текста для каждой. Строки располагаются по времени, чтобы повторы припева чередовались с куплетами. При равных временах сохраняется исходный порядок. Пустые строки и строки метаданных остаются исключёнными.

Исправление проверено через импорт соседнего LRC и через LRCLIB с контролируемым ответом HTTP. Синтаксис самой временной метки, обработка слов, ASR, выравнивание и воспроизведение не менялись. Исходный файл и сохранённый сырой LRC остаются прежними.

Production-файл: `python/backend/lyrics/codec.py`.

Изменение применяется при следующем чтении LRC. Уже готовые проекты автоматически не переписываются.

## 2. Перетаскиваемые файлы молча терялись при недоступности backend

После первого успешного запуска библиотека остаётся открытой во время временной недоступности backend. При перетаскивании файла она показывала приглашение к импорту, но обработчик drop завершался до чтения путей. После восстановления связи импорт не начинался; пользователю приходилось повторять действие без объяснения причины.

Теперь пути извлекаются из drop-события сразу и передаются существующей очереди команд библиотеки. Эта очередь уже ждёт готовности backend для файлов, открытых через оболочку Windows. При доступном backend импорт начинается сразу, при недоступном — после восстановления, однократно. Пустые списки путей в очередь не добавляются.

Production-файл: `frontend/src/pages/library/useLibraryDesktop.ts`. Код самой очереди, подписки, запуска приложения и backend не менялся.

## 3. Значок очереди показывал посторонние задачи как обработку песен

Число на кнопке очереди учитывало все активные backend-задачи, включая загрузку модели, AD Master, анализ записи и экспорт архива. Открываемая очередь показывает импорт и обработку песен. Поэтому пользователь мог видеть ненулевой счётчик без соответствующих песенных задач или завышенное число.

Для значка теперь отдельно подсчитываются только активные `SongImport` и `SongProcessing`: ожидание, выполнение и отмена. Завершённые задачи и задачи других типов не добавляются. Без активных песенных задач значок скрыт, сама кнопка по-прежнему открывает очередь.

Общий список `activeJobs` и расчёт библиотеки/готовности песен в комнате не менялись. Значок отражает число активных песенных задач, а не обязательно число видимых карточек: скрытые карточки и локальные временные карточки импорта имеют отдельное поведение.

Production-файл: `frontend/src/pages/library/hero/header/stats.tsx`.

Для четырёх изменённых frontend-файлов прошли TypeScript syntax/semantic с `tsconfig.app.json`, rules и architecture. Импортированные зависимости отдельно не проверялись. Для двух изменённых Python-файлов прошёл Ruff format/check; для одного production-файла — mypy с целью win32 и проверка архитектуры text/AST. Итоговая whitespace-проверка прошла.

Все три исправления просмотрены независимо. Блокирующих замечаний нет; финальные хеши сверены, дополнительных прогонов ради review не выполнялось.

## Границы результата

Frontend проверен в Linux/jsdom. Drop-сценарий использует настоящие DOM-обработчики, hook и очередь; native path/import и состояние backend контролируются fixture. Значок проверен на настоящем StatTile и React Query с контролируемыми данными API/задач.

Backend-импорт использует синтетическое аудио длительностью 0,2 секунды, настоящие FFmpeg/ffprobe, SQLite и queued API. Ответ LRCLIB контролируется тестом. Полное распознавание/выравнивание песни и модели не запускались.

Живой Windows/Electron-запуск здесь не выполнялся. Изменения не затрагивают синхронизацию комнат, аудиоустройства, запуск нескольких профилей, передачу проектов или DSP. Полные suites, сборки, CI, benchmarks и действия на рабочем сервере не запускались.

Дополнительно просмотрены обычные операции редактора, архив записей, настройки и обработка ошибок. Новых подтверждённых дефектов для правки в этих просмотренных путях не выбрано. Результат не означает, что в программе больше нет ошибок.

Полные журналы и коды завершения сохранены в рабочей сессии в `product-fixes-round9/`: `imports/red.log`, `imports/green.log` и Python gates; `desktop-import/drop-red.log`, `desktop-import/drop-green.log`; `queue-badge/badge-red.log`, `queue-badge/badge-green.log`; `types-and-rules.log`, `diff-check.log`.
