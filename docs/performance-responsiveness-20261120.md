# Отзывчивость karaoke_new_version: изменения и доказательства

Дата: 20 ноября 2026 года. Ветка: `perf/responsiveness-20261120`.
База: `main`, коммит `5a015a7ae8fc0516a448638beeeae7605e57b2ce`.
Этот документ фиксирует первый проход. Дополнительные находки, исправления и
измерения сохранены в [отчёте второго прохода](performance-responsiveness-pass2-20261120.md).

## Статус

В отдельной ветке подготовлены изменения интерфейса, очередей управления,
бэкенда, фоновой обработки и нативного DSP. Для обнаруженных дефектов добавлены
воспроизводящие тесты; изменённое поведение проверено целевыми наборами тестов.
Изменения закоммичены и опубликованы в ветке
[`perf/responsiveness-20261120`](https://github.com/Pro100Dimka/karaoke_new_version/tree/perf/responsiveness-20261120).
Эта работа не записывала коммиты в `main`; исходная база указана выше.

Работа с комнатами **не завершена**: обязательный живой прогон через
`start-multy.bat` в двух реальных Electron-окнах, с микрофонами и диагностикой
обоих участников, недоступен в этой Linux-среде. Результаты ниже не заменяют
этот прогон. Также не проверены реальные Windows-драйверы WASAPI/ASIO,
завершение дерева Windows-процессов и фактическая частота кадров на компьютере
пользователя. Поэтому отчёт не утверждает, что лаги исключены при любой нагрузке.

После первого отчёта пользователь явно разрешил публикацию. Ветка опубликована;
содержимое локальных и удалённых коммитов проверено по полным Git tree SHA.

## Что изменено

### Управление и интерфейс

1. **Очередь команд AudioService.** Частые изменения одного регулятора раньше
   занимали отдельные позиции в последовательной очереди, могли достигнуть её
   лимита и задерживали последующий `Stop`. Теперь соседние ещё не отправленные
   команды `SetGain`, `SetDspParameter` и `SetRadioGain` для одной цели объединяются
   в последнее значение. Уже отправленная команда не меняется. Чтение состояния,
   другой регулятор и команды жизненного цикла сохраняют порядок. Валидация
   аргументов и ранее принятый предельный срок ожидания сохраняются.
   Код: `frontend/electron/AudioServiceTransport.ts`.

2. **Сохранение настроек.** Вместо синхронной сериализации всех настроек на каждое
   движение ползунка изменения накапливаются в памяти и записываются раз в окно
   200 мс. Чтение сразу получает последнее состояние. При скрытии страницы,
   `pagehide` и `beforeunload` выполняется немедленная запись. Непрерывное движение
   не откладывает сохранение бесконечно.
   Код: `frontend/src/shared/preferences/preferences.ts`.

3. **Сортировка библиотеки.** Нормализованные строки и массивы кодовых точек
   вычисляются один раз для песни в рамках сортировки. Раньше они создавались
   заново внутри каждого сравнения. Сохранены порядок Unicode, правило разрешения
   равенства через ID и обновление результата после редактирования метаданных.
   Код: `frontend/src/pages/library/songs/librarySelectors.ts`.

4. **Отбор песен плейлиста.** Повторный линейный поиск через `includes` заменён
   одним множеством ID на операцию отбора.
   Код: `frontend/src/pages/library/songs/useLibraryCatalog.ts`.

5. **Подготовка фраз караоке.** Вместо повторного прохода по всем нотам для каждой
   строки строится индекс принадлежности слова фразам, затем ноты обходятся один
   раз. Сохранены исходный порядок нот и случай, когда слово встречается в
   нескольких строках.
   Код: `frontend/src/features/karaoke/show/ShowLayers.tsx`.

6. **Часы редактора нот.** Изменение позиции воспроизведения больше не пересоздаёт
   весь `PianoRoll`. Отдельная подписка обновляет указатель времени, подсветку нот
   и слов, а также автопрокрутку. Изменения документа, масштаба и режима слежения
   продолжают обновлять соответствующее представление. Проверены перемотка в обе
   стороны, пауза, ручной скролл, включение слежения, масштаб и очистка подписки.
   Адаптер опирается на DOM установленного `@neo-ui-kit/react` 1.4.15; при
   обновлении этого компонента необходимо повторить его целевые проверки.
   Код: `frontend/src/pages/editor/index.tsx` и `useEditorRollClock.ts`.

7. **Подсветка уже засчитанных нот.** Для неизменившегося множества попаданий
   добавлена проверка идентичности объекта до поэлементного сравнения. Новое
   попадание по-прежнему создаёт и публикует обновление.
   Код: `frontend/src/features/karaoke/KaraokeStage.tsx`.

8. **Расчёт оценки во время проигрыша.** Кэш оценки больше не сбрасывается на
   каждом тике, если нет новых данных о пении и ритме. Новая информация, загрузка,
   перезапуск и перемотка по-прежнему инвалидируют результат. В контрольном
   сценарии все поля итоговой оценки совпали с исходной реализацией.
   Код: `frontend/src/features/karaoke/show/performanceTracker.ts`.

### Бэкенд и фоновые задачи

9. **Медленные загрузки обложек.** Перед запуском блокирующей работы введён
   асинхронный лимит четырёх обложек. Очередь ожидающих запросов больше не занимает
   все рабочие потоки общего пула. После получения места в лимите проверяется,
   не отключился ли клиент, прежде чем запускать блокирующую работу.
   Регрессионный тест удерживает медленные загрузки и проверяет, что обычный API
   продолжает отвечать.
   Код: `python/backend/api/song_routes.py`.

10. **Попадание в кэш обложек.** Поиск готового файла больше не перечисляет весь
    каталог через `glob`. Проверяются только три поддерживаемых расширения
    конкретного ключа. Обработчики ошибок и конкурентных запросов сохранены.
    Код: `python/backend/infrastructure/artwork_cache.py`.

11. **Список записей.** Устранены повторные запросы к БД на каждую запись и загрузка
    всей истории анализов для отображения текущего статуса. Последние краткие
    результаты, существование песен и исходные записи для master-записей
    выбираются пакетно. Сохранены правила устаревших результатов, ревизий,
    отсутствующей песни, равного времени анализов и оценки живого исполнения.
    Код: `python/backend/analysis/`, `recordings/`, `songs/`,
    `infrastructure/sql_analysis.py`, `sql_recordings.py`, `sql_songs.py`,
    `api/recording_routes.py`.

12. **Реальный бюджет CPU для нормализации.** Выделенный конкретной задаче бюджет
    потоков передаётся в стадию нормализации. Раньше стадия использовала глобальный
    бюджет даже при меньшем разрешённом числе потоков задачи. Сохранены параметры
    обработки и ключи кэша; контрольный выходной PCM совпал побайтно.
    Код: `python/backend/processing/audio_pipeline.py`, `normalize_stage.py`.

13. **Пулы фильтров FFmpeg.** Нормализация передаёт явный `-filter_threads` в рамках
    бюджета; построение waveform ограничивает пул фильтра одним потоком.
    Документация FFmpeg отдельно описывает этот пул и его исходный выбор числа
    доступных CPU [1]. Изменение уменьшает конкуренцию фоновых задач за ресурсы;
    ускорение самой нормализации по длительности не заявляется.
    Код: `python/backend/infrastructure/ffmpeg_audio.py`, `ffmpeg_media.py`.

### Аудио, комнаты и жизненный цикл

14. **Медленные вычисления на затухающем DSP-сигнале.** После импульса фильтры
    сохраняли чрезвычайно малые ненулевые значения. Добавлен ограниченный областью
    вызова режим FTZ/DAZ для x64 в DSP и realtime-контексте. Он восстанавливает
    исходный регистр режима вычислений после выхода. Это адресная обработка
    субнормальных значений [2]; глобальный `fast-math` не включён. Тесты проверяют
    восстановление режима, затухание, точный обход выключенного DSP, конечность
    результата, эффекты и отсутствие нарушений realtime-контекста.
    Код: `AudioService/src/dsp/ScopedNoDenormals.hpp`, `DspChain.cpp`,
    `AudioService/src/realtime/RealtimeInstrumentation.hpp`.

15. **Объединение библиотек участников.** Повторное копирование и сканирование
    всей накопленной библиотеки для каждой удалённой песни заменено индексами
    source/project hash. Сохранены приоритет совпадения ID, выбор первого
    действующего совпадения и порядок после замены. Для отсутствия удалённых
    песен предусмотрен ранний возврат. Старая и новая реализации дали одинаковый
    результат на 10 000 воспроизводимых случайных наборов.
    Код: `frontend/src/application/room/roomLibrary.ts`.

16. **Публикация библиотеки комнаты.** Подпись каталога сохраняется вместе с
    загруженными песнями и пересчитывается при существующем обновлении данных.
    Проверка передачи раз в секунду больше не сортирует и не сериализует весь
    неизменившийся каталог. Сохранены обновления по событиям и существующий TTL.
    Код: `frontend/src/application/room/RoomLibraryPublisher.ts`.

17. **Очередь настроек голоса в комнате.** Соседние ещё не отправленные изменения
    одного участника в одном контексте комнаты объединяются по последним значениям
    полей. Начальная синхронизация и другой участник остаются границами очереди.
    Поколения изменений отдельных полей защищают новые оптимистические значения
    от старого ответа или ошибки. Выход из комнаты не позволяет старому контексту
    отправлять обновления в новую комнату.
    Код: `frontend/src/application/room/RoomVoiceSettingsCoordinator.ts`.

18. **Принудительное завершение сервиса Windows.** Блокирующий `spawnSync(taskkill)`
    заменён асинхронным запуском с пределом ожидания 5 секунд. Повторные запросы
    остановки ждут одну операцию; выход процесса-запускателя не завершает ожидание
    раньше помощника, уничтожающего дерево процессов. Ошибка или таймаут помощника
    вызывают ограниченный резервный путь остановки собственного процесса.
    Проверка выполнена с имитацией Windows, реальный `taskkill` ещё не проверен.
    Код: `frontend/electron/ServiceProcess.ts`.

Наборы частично пересекаются; их количества нельзя складывать в число уникальных
тестов. Это целевые проверки затронутых рисков, а не полный прогон всех тестов
репозитория. До исправлений новые воспроизводящие тесты подтверждали дефекты.

Попытка проверки настоящим Chromium в текущей среде остановилась до запуска
страницы: создание сокета профиля запрещено (`socket() failed: Operation not
permitted`). Поэтому проверки редактора с настоящим установленным компонентом
UI-kit в jsdom подтверждают обновления DOM и взаимодействия, но не реальную
отрисовку, FPS и работу графического драйвера.

Последняя сборка сообщает главный JS-чанк 1 563,22 kB, gzip 471,40 kB и стандартное
предупреждение Vite о чанке больше 500 kB. Порог предупреждения не повышался.
Время холодного запуска и затраты первоначальной отрисовки большого документа
этими измерениями не подтверждены.

### Повторение целевых проверок

На Windows используются существующие команды проекта из корня checkout; списки
можно передавать несколькими аргументами. Примеры для новых регрессий:

```bat
check.bat frontend electron/AudioServiceTransport.test.ts electron/ServiceProcess.test.ts
check.bat frontend src/pages/editor/EditorPage.clock.test.tsx src/shared/preferences/preferences.persistence.test.ts
check.bat frontend src/application/room/RoomVoiceSettingsCoordinator.queue.test.ts src/application/room/roomLibrary.performance.test.ts
check.bat backend --workers=1 tests/test_cover_responsiveness.py tests/test_recording_list_responsiveness.py tests/test_processing_cpu_admission.py
check.bat audio dspSilenceSettlesWithoutSubnormalTails realtimeScopeRestoresFloatingPointMode
```

Тест с медленными обложками и временные измерения запускаются последовательно,
чтобы конкурирующие тестовые задачи не искажали результат. Тесты производительности
сортировки, подготовки фраз, плейлистов и оценки находятся рядом с изменёнными
компонентами и входят в итоговый прогон 138 тестов.

В Linux использовались установленные инструменты проекта: Vitest с двумя
воркерами, `tsc -b tsconfig.app.json`, `tsc -p electron/tsconfig.json --noEmit`,
`vite build`, pytest, Ruff, mypy и собранный нативный test runner. `check.bat`
в этой среде не запускался.

Точный состав трёх итоговых групп pytest (пути от `python/`):

- 45 тестов: `tests/test_recording_list_responsiveness.py`,
  `tests/test_recording_historical_analysis.py`, `tests/test_recordings_analysis.py`,
  `tests/test_recording_registration_ownership.py`, `tests/test_recording_rename_deletion.py`,
  `tests/contracts/test_sql_repository_contracts.py`, `tests/test_cover_responsiveness.py`,
  `tests/test_artwork_cache_failures.py`.
- 19 тестов: `tests/test_songs_api.py`.
- 42 теста: `tests/test_processing_cpu_admission.py`,
  `tests/test_processing_normalized_source.py`, `tests/test_ffmpeg_serialization.py`,

  `tests/test_cache_query_provenance.py::test_normalization_does_not_reuse_audio_cached_before_loudness_protection`.

Нативный runner запускался отдельно для каждого из следующих 16 имён; итоговые
