Karaoke Word Sync: воспроизведение проверок v4 → финальная версия

ОБЛАСТЬ ПРИМЕНИМОСТИ

<PROJECT> — каталог исходников, содержащий python/, frontend/, kaggle/ и check.bat.
<EVIDENCE> — каталог доказательств из пакета, содержащий harness/ и ctc-evidence/.
Команды ниже используют уже установленное окружение зависимостей проекта.
Названия python/pytest означают интерпретатор этого окружения. Новые модели или
зависимости для исправления не добавлялись. Не запускайте тесты или модели
параллельно с измерением производительности.

1. РЕГРЕССИИ БЕЗ ЗАГРУЗКИ AI-МОДЕЛЕЙ

Из каталога <PROJECT>/python:

python -m pytest -q tests/test_inactive_core_review.py tests/test_confirmed_voice_onsets.py tests/test_guidance_acoustic_fallback.py

Это 20 новых параметризованных проверок. Они используют управляемые CTC/акустические
данные; не устанавливают истинные времена слов в коммерческих записях. Проверяются
слабое ядро вне вокальной активности, совместное уточнение локального окна,
сохранение соседей, настоящие короткие слова и начальные согласные, а также отказ
от нулевой интерполяционной альтернативы при наличии подходящего CTC-результата.
Существующие expected-значения тестов не менялись.

Полный поддерживаемый backend gate из корня проекта в Windows:

check.bat backend

Его Python-часть из <PROJECT>/python:

python scripts/run_checks.py --require-dev-tools

Официальный gate останавливается при первой неуспешной стадии. Для полного списка
ошибок в нашем исследовании harness/run_backend_gate.py последовательно выполнил
все те же стадии, сохранил их ненулевые exit codes и полный pytest. Это расширенный
инвентаризатор результатов, а не способ объявить gate успешным.

2. ПЕРЕНОСИМАЯ ПРОВЕРКА НА АРХИВНЫХ РЕАЛЬНЫХ MMS-ПРИЗНАКАХ

Из <EVIDENCE> (подставить реальный абсолютный путь <PROJECT>/python):

python harness/reproduce_acoustic_suffix.py --repo-python <PROJECT>/python --features ctc-evidence/pivovarov_dezhavyu_ua.npz --output reproduced-acoustic-suffix.json

NPZ содержит уже рассчитанные MMS scores, шаг кадров, вокальную активность и
акустические начала. Скрипт повторяет локальную CTC/word-guidance селекцию на этих
признаках. Не выполняются ASR, MMS inference, Demucs или CREPE и не загружаются
веса AI; библиотеки NumPy/PyTorch/torchaudio из окружения проекта всё равно нужны.

В финальной версии positiveConfidence, acousticSuffixRetained и followingUnchanged
должны быть true. trueOnsetVerified намеренно остаётся false. Это доказательство,
что подходящий CTC-кандидат сохраняет внутренние буквенные опоры и соседнее слово,
а не доказательство истинного начала слова «Хвилями» или фонетической точности
каждой буквы. Не трактуйте успешный CTC как независимую акустическую разметку.
При запуске на исходной v4 потеря CTC-опор проявляется в этих же данных.

3. ПОЛНЫЙ ПОВТОР SPEECH.ALIGN НЕ ЯВЛЯЕТСЯ САМОСТОЯТЕЛЬНО ПЕРЕНОСИМЫМ

В пакет не включены полные записи исполнителей, их вокальные/инструментальные
дорожки и полные тексты песен. Источники, интервалы фрагментов, хеши и ограничения
приведены в доказательствах и основном отчёте. Один NPZ из пункта 2 НЕ заменяет
waveforms/transcripts, необходимые для полного speech.align.

Для полного повтора необходимо получить указанные публичные записи, восстановить
точно тот же фрагмент/декодирование и раздельные дорожки, проверить SHA-256, подготовить
точный слышимый текст, язык и manifest paths. Для нового вычисления нужны уже
используемые модели проекта и соответствующие веса. Для строгого replay нужны
полные acoustic-cache.npz (включая waveforms), alignment-evidence.json, asr-cache.json,
metadata.json и исходные файлы, указанные в manifest. Эти большие полные кэши
не следует считать включёнными только потому, что в пакете есть их метаданные.

Оригинальный исследовательский run_alignment.py содержит путь
/tmp/karaoke-sync-v4/model-downloads.json для model-proof, читает его даже в replay
и хранит локальные пути исследовательской машины. Для другой машины нужно
восстановить/явно перенастроить этот proof на проверенные сведения о своих весах
и исправить пути manifest. В скрипте также используется Unix resource.
Не создавайте фиктивный model-proof и не подменяйте несовпавший SHA-256.

Последовательность исследования: baseline fresh → baseline strict replay → final
strict replay с одинаковыми модельными результатами. Все timingHints должны быть
пустыми. Независимые word/phone labels подаются только оценщику, а не alignment.
Baseline fresh/replay должны давать одинаковый payload. Неизвестный ASR-контекст
в replay — ошибка, а не разрешение запустить модель или вернуть пустой ответ.
При отсутствии независимой разметки нельзя считать ошибки начала/конца в мс
относительно собственных ASR/CTC-предположений.

4. ПРОИЗВОДИТЕЛЬНОСТЬ: ДВА РАЗНЫХ ЭКСПЕРИМЕНТА

benchmark-summary.json сохраняет исходный ABBA с отдельными процессами, двумя
сериями по 9 измерений на версию и 3 прогревами. Сырые выборки не удалялись.
На двух фрагментах агрегированная медиана финальной версии оказалась примерно
на 11–12% выше; это наблюдение не заменено результатом другого эксперимента.

paired-benchmark-result.json и benchmark-paired-artists.json — отдельный контроль
в одном процессе: 3 прогревочные пары и 18 чередующихся AB/BA-пар. До каждого таймера
переключаются только 5 проверенных изменённых AST-функций baseline/final и alias
speech.with_voice_onsets. Остальные общие AST-узлы/файлы проверены на равенство.
Каждый результат после таймера точно сравнивается со своим frozen payload.
Этот контроль уменьшает влияние межпроцессного дрейфа; разброс сохраняется и
не позволяет обещать постоянное ускорение или точность измерения до 1%.

Оба эксперимента используют один строгий кэш и запрещают новые model calls/cache
misses. Из времени исключены импорты, декодирование, модели, создание модельной
маски singing_frames, сериализация трасс и проверки равенства/хешей. Это время
локальной обработки после повторного использования модельных результатов,
а не полное время обработки песни. Для повторения нужны восстановленные полные
кэши и waveforms из пункта 3. Команды и guards описаны в BENCHMARK.txt; параметры
нового paired-режима доступны в benchmark_paired_alignment.py --help.
