- **Восстановление записей после сбоя не подключено.** `RecordingReconciliation` читает `recordings/*/recording-recovery.json` (спецификация §122), но рабочий код эти файлы не создаёт: `write_recovery_descriptor` вызывается только из тестов.
- **Устаревшие ноты у обработанных ранее песен.** Алгоритм нот и расстановки слов изменён, а версии `melody-1` / `pipeline-1` не подняты. Маршрут `POST /songs/{id}/processing/melody` есть, кнопки «пересчитать ноты» в интерфейсе нет.
- **Неиспользуемые маршруты комнат.** `POST /rooms/{id}/disconnect` и `POST /rooms/{id}/resolve-host` не вызывает ни один клиент. Удаление требует живой проверки комнат (AGENTS.md).
- **Ревью настроек аудио (незакоммиченная работа).**
  - После отката ASIO список буферов сужается до одного сохранённого значения.
  - При смене бэкенда из формы перестаёт синхронизироваться частота дискретизации.
  - Подсказка по настройке ASIO скрывается, если установлен любой другой ASIO-драйвер.
  - `capabilities()` в `audioClient.ts` требует каналов > 0, а проверка устройств ASIO — нет.
- **Красные проверки правил.** Архитектурный гейт Python (код комнат, `voice_relay.py`) и `npm run check:rules` (длина файлов, хранилище в тестах) не проходят.
