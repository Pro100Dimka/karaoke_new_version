1. ПРОБЛЕМА И ПОДТВЕРЖДЁННЫЕ ПРИЧИНЫ

Ожидание: при достижении сохранённого начала следующей буквы граница заливки находится у этой буквы; видимый последний звук остаётся активным до сохранённого word.end.
Фактически: karaokeLyrics.ts рассчитывал долю по числу звучащих букв. KaraokeLyrics из закреплённого @neo-ui-kit/react 1.3.2 применяет её как долю физической ширины span(word.text + пробел) и округляет до целого процента. Пропорциональный шрифт, знаки препинания и хвостовой пробел нарушают соответствие. Это воспроизведено в настоящем Electron/Chromium на сохранённых данных русских и украинских вокальных фрагментов, а не только в jsdom.

Дополнительно UI считал ь/ъ и комбинируемые диакритические знаки отдельными звучащими символами, хотя у них нет отдельного произношения/CTC-токена. На реальном «отдать» собственный интервал ь составлял 300 мс в одном повторе и 60 мс в другом. Исправление объединяет отображение такой группы; оно не доказывает акустическую длительность согласного «ть».

При проверке нового преобразования найден и исправлен его пограничный случай: в «мо́ре» и decomposed «ёлка» Range для диакритики совпадает с Range базовой буквы; самостоятельный интервал диакритики останавливал заливку гласной. Два теста сначала воспроизвели этот дефект, затем прошли после исключения Unicode Marks как самостоятельных звуков.

2. ТРАССИРОВКА И ГРАНИЦА ИЗМЕНЕНИЯ

speech.align: CTC/align_words → align_guided → with_word_guidance → with_voice_onsets → with_sung_ends → ordered → rate_review_indices/boundary_conflicts → локальная совместная проверка при необходимости → повторные onset/end/ordered только при принятом изменении → with_sung_letters → alignment_payload.
Затем processing.algorithms.construct_document/_word_with_notes строят пересечения общей мелодии со словами; lyrics.codec сериализует абсолютные времена. EditorWord использует относительные времена букв. Ошибка, исправленная в v3, возникает после этого: letterProgress → процент ширины компонента KaraokeLyrics.

В v3 backend, аудио, границы слов и букв, сохранённые ноты, модели, зависимости, формат проектов и Kaggle notebook не изменены. Не добавлен коэффициент замедления, минимальная длительность или поправка времени. existing currentLineIndex/buildLines не изменены. Переходы строк проверены существующими тестами; полное воспроизведение песни на целевой Windows-машине не выполнено.

3. ИЗМЕНЁННЫЕ ФАЙЛЫ

- frontend/src/features/karaoke/karaokeLyrics.ts: letterProgress/timedLetterProgress принимают необязательную геометрию букв; сохранённые времена переводятся в фактические координаты. Беззвучные знаки, пробелы и диакритика не получают самостоятельного интервала. Старый вызов с двумя аргументами совместим; fallback без букв остаётся приблизительным.

Между этими событиями используются сохранённые размеры; layout effect задаёт точную заливку на текущем времени без округления до 1%. Observer и listener удаляются при очистке.
- frontend/src/features/karaoke/KaraokeStage.tsx: подключение адаптера к существующим словам через id и выбранный шрифт. Новых элементов управления нет.

Diff относительно входной v2: 4 файла; production — 3 файла, +106/-14 строк; тесты — новый файл, 181 строка. Суммарно +287/-14. Внешний UI-пакет и node_modules не редактировались. Архив содержит также отчёт и воспроизводимые доказательства; это не дополнительные изменения приложения.

Эти геометрические ошибки устранены при неизменённых данных.

10. ОСТАВШИЕ ПРОБЛЕМЫ И МАТЕРИАЛЫ ДЛЯ ЗАКРЫТИЯ

- Нужен точный waveform, породивший uncertain_scores, с offset, preprocessing и хэшем; родственная запись не подтверждает onset9.10.
- Нужны полные проблемные RU/UK проекты: исходная песня, использованный reference-vocal, instrumental, lyricsSync.json и processing report. Желательны конкретные слова/фрагменты с наблюдаемой ошибкой. Для численной акустической оценки нужна независимая прослушанная разметка начала/конца и диапазоны неопределённости слитных переходов; для букв — фонемные/произносимые группы.
- В exact paired «один» внутренние буквенные границы остаются противоречивыми; UI теперь правильно отображает сохранённые значения, но не превращает их в акустическую истину.
- Подтверждён синтетический предел диагностики ordered: дом1.00–1.30 и сосед1.10 обрезаются до1.00–1.10 без флага, если нет matched ASR. Потеря200мс ниже порога250мс, остаток100мс выше порога80мс. На реальных23малых clips причиной была штатная onset-компенсация; снижение порога без независимого подтверждения создаёт ложные reviews. Порог не менялся, остаточный риск сохранён явно.
- Новые полные проекты/песни не создавались, существующие записи не перезаписывались. Старый fallback без букв остаётся приблизительным.
- Обязательная живая проверка по AGENTS.md на целевом Windows/Electron, с реальным звуком и применимыми сценариями start/pause/resume/seek/stop, недоступна в этой Linux-среде. Offscreen Electron проверяет геометрию, а не этот gate.

Проверенные изменения готовы к просмотру и применению. Полная задача акустической синхронизации остаётся незавершённой по перечисленным ограничениям.
