# Воспроизведение измерений

Команды ниже выполняются из корня этого набора. Используйте Python с установленными зависимостями проекта; дополнительные AI-модели не требуются. Не запускайте вычислительные команды одновременно с измерением скорости другой обработки.

## Проверить целостность

```sh
sha256sum -c STAGING-FILES.sha256
```

Эта ведомость относится к выбранному проверочному набору до последующих дополнений итогового отчёта. `STAGING-INVENTORY.json` отдельно хранит хеши исходных файлов; 12 трассировок распространяются без ASR-запросов и транскриптов. Для них исходный и поставляемый хеши различаются намеренно. Сырые оригиналы v3 при подготовке не менялись.

## Пересчитать ошибки слов без аудио и моделей

```sh
python3 compare_words.py --root . --after gtsinger-final --output word-comparison-reproduced.json
```

Сравнивайте `metrics` и `rows` с `gtsinger-final/word-comparison.json`. Пути в секции происхождения могут различаться при переносе; численные метки и прогнозы остаются теми же.

## Перенос исторических скриптов

Скрипты и метаданные сохранены с оригинальными рабочими путями, чтобы сохранить их исходные хеши. Утилита ниже создаёт **новую отдельную копию**, заменяя только фиксированные префиксы путей. Она не изменяет этот пакет, не загружает файлы и не запускает модели. Каталог назначения должен отсутствовать.

```sh
python3 reproduction/prepare_replay_workspace.py \
  --source . \
  --destination /absolute/path/to/replay-workspace \
  --project /absolute/path/to/karaoke-project
```

Для исторических проверок, которым нужен v3, дополнительно передайте `--baseline /absolute/path/to/v3-project`. Численные данные не пересчитываются. `RELOCATION.json` перечисляет заменённые пути и новые хеши; исходная ведомость остаётся исторической, а `WORKSPACE-FILES.sha256` проверяет перенесённую копию.

Из созданной рабочей копии:

```sh
python3 letters/compare_external_phones.py \
  --prediction-dir gtsinger-final --output phone-comparison-reproduced.json --label v4

python3 notes/compare_real_notes.py \
  --after-dir gtsinger-final --output-dir notes/reproduced
```

Обе команды используют готовые численные файлы. Проверка нот вызывает существующие функции проекта, но не запускает CREPE заново. Для обеих версий она использует одинаковые сохранённые pitch-точки.

## Восстановить исходные фрагменты для графиков

Аудио не включено. При необходимости получить именно зафиксированные публичные GTSinger-файлы:

```sh
python3 audio-reference/fetch_gtsinger_reference.py --destination audio-reference/gtsinger
python3 plot_real_boundary_comparison.py --root . --output real-boundary-reproduced.png
```

Загрузчик сверяет размеры и SHA256, использует публичные URL закреплённой ревизии и не загружает AI-модели. До загрузки ознакомьтесь с сохранённой лицензией источника. Рисунок использует исходный WAV; не меняет звук, его длительность или положение.

## Повторная обработка моделями

`gtsinger-baseline/run_alignment.py` принимает `--repo-python`, `--inputs`, `--case`, `--output`. В `inference-inputs.json` / `additional-inference-inputs.json` есть только короткий текст, путь/хеш аудио, язык и длительность; эталонные границы туда не передаются. Для свежего запуска используйте новый каталог вывода и уже установленный каталог моделей через `AD_VOICE_MODELS`. Установка новых моделей или запуск полного файла песни не являются частью пересчёта включённых метрик.

Исторический `--cache-from` и `letters/verify_helper_extraction.py` дополнительно требуют исключённых ASR/CTC-кешей. Поэтому пакет хранит их фактические результаты и хеши, но не обещает воспроизвести побайтово такой replay без этих входов. Свежий запуск может заново получить модельные результаты; сравнивать его следует с независимыми метками, не подавая их в алгоритм.

Профильные регрессионные тесты запускаются из поставляемого отдельно проекта. Исторические RED/GREEN-журналы в этом каталоге показывают порядок воспроизведения и проверки; актуальный полный gate и его оставшиеся падения описываются итоговым отчётом.

## Проектные русские и украинские фрагменты

Следующие команды используют уже существующие тестовые fixtures проекта; новые внешние записи, ASR или MMS-вычисления не загружаются. Существующая обработка активности голоса выполняется обычным кодом.

```sh
python3 legacy-final/clean_replay.py --repo /absolute/path/to/project \
  --out odin-reproduced.json --local-asr --label reproduced
python3 legacy-final/replay_sadvit.py /absolute/path/to/project/python \
  sadsvit-reproduced.json --label reproduced
```

`legacy-final/refreshed-source-verification.json` подтверждает совпадение численных времён до и после последнего обновления исходного кода. Поля расстояния до акустического интервала в SadSvit относятся к ранее сохранённым приблизительным диапазонам сигнала; это **не** ошибка относительно точной независимой слуховой разметки и не часть GTSinger-метрик.
